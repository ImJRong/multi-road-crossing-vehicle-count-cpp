## 二、两个仓库的分工

| 仓库 | 内容 | 角色 |
|---|---|---|
| `multi-road-crossing-vehicle-count-cpp`（本仓库） | C++ 板端实现、网页版、`docs/技术文档.md`、`docs/代码走读.md` | **主力**，全部新代码进这里 |
| `multi-road-crossing-vehicle-count` | Python 原型、模型转换脚本、`MEMORY.md`、原理推导与实验记录 | 算法源头与文档仓库 |

板端 C++ 代码只在本仓库改。Python 版仓库里不再保留 C++ 源码副本（2026-11-06 已删除，避免两份不一致）。

## 三、板子上的本地副本

板子 `~/code/` 不是 git 仓库，代码与文档都从 PC 同步过去。2026-11-06 起，板子 `~/code/docs/` 放了一份完整副本，包含本仓库没有的那几份（`MEMORY.md`、`head4_原理详解.md`、`实操手册.md`、`INT8验证方案.md`、`设计要点.md`、`tools脚本清单.md`），另有 `figures/`（11 张配图）与 `screenshots/`（3 张现场截图）。

板子刷新文档的命令（在 PC 的仓库目录里执行）：

```bash
scp MEMORY.md orangepi@192.168.1.105:~/code/
scp -r docs/* orangepi@192.168.1.105:~/code/docs/
```

`docs/` 下的文件是**只读副本**，改了不会回流到仓库；要改请改 PC 上的仓库再提交。

## 四、阅读顺序建议

第一次接手，按这个顺序读：

1. 本仓库 `README.md` —— 项目是什么、怎么跑起来
2. `docs/技术文档.md` —— 为什么这么设计，实测数据在哪
3. `docs/代码走读.md` —— 逐个文件过一遍代码
4. Python 版仓库 `MEMORY.md` —— 踩过的坑、哪些路已经堵死，**动手前必看**
5. 需要改模型时再看 `docs/head4_原理详解.md` 与 `docs/实操手册.md`
