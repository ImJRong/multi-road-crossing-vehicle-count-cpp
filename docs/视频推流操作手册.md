# 视频推流操作手册

板子没有摄像头。用 PC 上的 MP4 伪装成 RTSP 摄像头，板子照常拉流，代码一行不用改。

## 一、装在哪儿

| 程序 | 路径 | 作用 |
|---|---|---|
| MediaMTX | `D:\tools\mediamtx\mediamtx.exe` | RTSP 服务器，监听 8554 端口 |
| ffmpeg | `D:\tools\ffmpeg\bin\ffmpeg.exe` | 读 MP4，编码后推给 MediaMTX |
| 配置文件 | `D:\tools\mediamtx\mediamtx.yml` | 所有配置都在这一个文件里 |

ffmpeg 没有加进系统 PATH，所以配置文件里必须写完整路径 `D:/tools/ffmpeg/bin/ffmpeg.exe`。

## 二、数据怎么走

```
D:/.../data/videos/test2.mp4
        |  ffmpeg -re -stream_loop -1 （按原速读、循环）
        v
rtsp://127.0.0.1:8554/test2   （MediaMTX 内部路径）
        |
        v
板子: rtsp://192.168.1.101:8554/test2   （192.168.1.101 = PC 的局域网 IP）
```

## 三、配置改在哪儿

打开 `D:\tools\mediamtx\mediamtx.yml`，滚到文件最后。第 882 行是 `paths:`，下面就是四路：

```yaml
paths:
  # ===== 本项目: 本地 MP4 当摄像头 =====
  test1:
    runOnInit: D:/tools/ffmpeg/bin/ffmpeg.exe -nostdin -loglevel error -re -stream_loop -1 -i D:/multi-road-crossing-vehicle-count/data/videos/test1.mp4 -an -c:v libx264 -preset ultrafast -tune zerolatency -rtsp_transport tcp -f rtsp rtsp://127.0.0.1:8554/test1
    runOnInitRestart: yes
  test2:
    runOnInit: D:/tools/ffmpeg/bin/ffmpeg.exe -nostdin -loglevel error -re -stream_loop -1 -i D:/multi-road-crossing-vehicle-count/data/videos/test2.mp4 -an -c:v libx264 -preset ultrafast -tune zerolatency -rtsp_transport tcp -f rtsp rtsp://127.0.0.1:8554/test2
    runOnInitRestart: yes
  test3:
    runOnInit: D:/tools/ffmpeg/bin/ffmpeg.exe -nostdin -loglevel error -re -stream_loop -1 -i D:/multi-road-crossing-vehicle-count/data/videos/test3.mp4 -an -c:v libx264 -preset ultrafast -tune zerolatency -rtsp_transport tcp -f rtsp rtsp://127.0.0.1:8554/test3
    runOnInitRestart: yes
  test4:
    runOnInit: D:/tools/ffmpeg/bin/ffmpeg.exe -nostdin -loglevel error -re -stream_loop -1 -i D:/multi-road-crossing-vehicle-count/data/videos/test4.mp4 -an -c:v libx264 -preset ultrafast -tune zerolatency -rtsp_transport tcp -f rtsp rtsp://127.0.0.1:8554/test4
    runOnInitRestart: yes
```

缩进只有两档：`test1:` 前面空 2 格，`runOnInit:` 前面空 4 格。多一格少一格都起不来。

## 四、推一个新视频

把视频文件放进 `D:\multi-road-crossing-vehicle-count\data\videos\`，假设叫 `test5.mp4`。

用记事本打开 `D:\tools\mediamtx\mediamtx.yml` 滚到最后，复制 `test4:` 那三行贴到文件末尾，然后改三个地方：

| 改什么 | test4 原值 | 改成 |
|---|---|---|
| path 名 | `test4:` | `test5:` |
| 输入文件 | `.../videos/test4.mp4` | `.../videos/test5.mp4` |
| 推流地址最后一段 | `rtsp://127.0.0.1:8554/test4` | `rtsp://127.0.0.1:8554/test5` |

存盘，关掉 mediamtx 的黑窗口，重新双击 `D:\tools\mediamtx\mediamtx.exe`。板子上填 `rtsp://192.168.1.101:8554/test5`。

不想要某一路，把那一整段三行删掉，重启 mediamtx 就行。

## 五、每个参数在干什么

| 参数 | 含义 | 去掉会怎样 |
|---|---|---|
| `-nostdin` | 不读键盘输入 | 后台跑时可能卡住 |
| `-loglevel error` | 只打印错误 | 刷屏 |
| `-re` | 按源帧率读 | 全速读完，1 秒推完 15 分钟的片子 |
| `-stream_loop -1` | 无限循环 | 推一遍就停 |
| `-i <路径>` | 输入文件 | — |
| `-an` | 丢掉音轨 | 白推一路音频，浪费带宽 |
| `-c:v libx264` | 视频编码器 | — |
| `-preset ultrafast` | 编码速度优先 | 编码慢，可能跟不上 |
| `-tune zerolatency` | 零延迟 | 多几帧缓冲 |
| `-rtsp_transport tcp` | 推流走 TCP | UDP 丢包，日志刷 `RTP packets lost`，画面花屏 |
| `-f rtsp <地址>` | 输出格式和地址 | — |

这里没有加 `-r 20`。源是多少帧就推多少帧：test1 是 12、test2 是 30、test3 是 24、test4 是 8。加了 `-r 20` 会变成两种结果，12fps 的源产生重复帧，30fps 的源丢真帧，两边都会让计数结果没法跟旧数据比。

## 六、日常怎么用

启动只要一步：

```powershell
Start-Process "D:\tools\mediamtx\mediamtx.exe" -WorkingDirectory "D:\tools\mediamtx"
```

或者直接双击 `D:\tools\mediamtx\mediamtx.exe`。起来之后它会自己拉起 4 个 ffmpeg 进程，不用手动开。

停止就是关掉那个黑窗口，或者在 PowerShell 里：

```powershell
Get-Process mediamtx, ffmpeg -ErrorAction SilentlyContinue | Stop-Process -Force
```

顺序上先开 mediamtx，再开板子的 `traffic_web_quad`。反过来板子连不上流。

板子端启动：

```bash
cd ~/code && ./traffic_web_quad 8081
```

只要给端口，不写默认 8081。配置名默认 `test1`～`test4`，帧率默认跟源视频。然后浏览器打开 `http://<板子IP>:8081`。

换源在监控台顶部的「视频源」卡片里，四行对应四路：左边「类型」选「视频流」，中间输入框填 `rtsp://192.168.1.101:8554/test2`，右边「配置」选这份视频对应的 json（决定 ROI、计数线、跟踪阈值），点「接入」等一两秒，圆点变绿、显示 `运行中 · 30 fps` 就成了。

运行中类型、地址、配置都锁死改不了，要先点「断开」。断开后地址还留着，再点「接入」就恢复。

板子端停止：

```bash
pkill -f "[t]raffic_web_quad"
```

方括号不能省，否则 `pkill -f` 会把执行这条命令的 shell 也匹配上一起杀掉。

## 七、板子上填什么地址

PC 的局域网 IP 是 192.168.1.101（WLAN 网卡）。

| 视频 | 分辨率 | 源帧率 | 板子填 |
|---|---|---|---|
| test1 | 1280x674 | 12 | `rtsp://192.168.1.101:8554/test1` |
| test2 | 1280x720 | 30 | `rtsp://192.168.1.101:8554/test2` |
| test3 | 1280x720 | 24 | `rtsp://192.168.1.101:8554/test3` |
| test4 | 1280x960 | 8 | `rtsp://192.168.1.101:8554/test4` |

这个 IP 会变，换网络或者路由器重新分配都会导致变化。查法：PC 上跑 `ipconfig`，看「无线局域网适配器 WLAN」那行的 IPv4 地址。

## 七点五、本地视频和视频流有什么区别

网页上每一路可以单独选，四路任意组合。

| | 本地视频 | 视频流 |
|---|---|---|
| 填什么 | 下拉框选 `data/videos/*.mp4` | 手填 `rtsp://` / `http://` / `https://` 地址 |
| 播完怎么办 | 重新从头播，计数清零、编号从头开始 | 永不结束；断流自动重连（2→4→6→8→10 秒退避），计数不清零 |
| 帧率 | 跟文件自带帧率 | 跟流帧率，不额外限速 |
| 用途 | 离线验证、批量对比 | 模拟真实摄像头 |

同样的内容走流和走文件，计数结果应该一致，这是条便宜的自检：把 test2 分别用本地文件和视频流各跑一次，数对不上就说明流这条路有问题。

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 板子 `No route to host` | 填的 IP 不对 | `ipconfig` 重新查 PC 的 IP |
| 板子 `Connection refused` | mediamtx 没在跑 | 双击 mediamtx.exe |
| 画面花屏、日志刷 `RTP packets lost` | 推流走了 UDP | 确认命令里有 `-rtsp_transport tcp` |
| 板子帧率只有原来的一半 | RTSP 是 H.264 软解码，吃 CPU | 正常现象，板子默认不启用硬件解码 |
| yml 改了但没生效 | 没重启 | 关掉 mediamtx 重开 |
| mediamtx 启动即退出 | yml 缩进错了 | 用空格不用 Tab；`testN:` 空 2 格，`runOnInit:` 空 4 格 |
| 板子日志刷 `Connection refused` | 填了 `127.0.0.1` | 那是板子自己，要填 PC 的 IP |
| 板子日志只偶尔打一行「打不开视频流」 | 退避重试在起作用 | 正常，修好地址后 10 秒内自己连上 |

## 九、怎么验证通了

PC 上确认推流正常：

```powershell
D:\tools\ffmpeg\bin\ffprobe.exe -rtsp_transport tcp rtsp://127.0.0.1:8554/test2
```

板子上确认能拉到：

```bash
ffprobe -v error -rtsp_transport tcp -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate -of default=nw=1 rtsp://192.168.1.101:8554/test2
```

正常会输出：

```
codec_name=h264
width=1280
height=720
r_frame_rate=30/1
```
