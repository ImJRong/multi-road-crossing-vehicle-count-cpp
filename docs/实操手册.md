## 一、训练数据怎么准备

`data/videos/` 下那 4 个视频是最终测试集，不参与训练。用测试集训练会让评估分数失真。

数据来源要覆盖多个不同摄像头的画面，而不是同一个视频切很多帧。

| 项 | 目标 |
|---|---|
| 总张数 | 150 ～ 300 张 |
| 摄像头数量 | 20 个以上 |
| 每个摄像头 | 5 ～ 20 张，覆盖不同时段和车流密度 |

同一摄像头连拍的帧相似度超过 95%，标 100 张等同于同一张的 100 个副本。宁要 20 个机位各 10 张，不要单个机位 200 张。

```bat
python tools\extract_frames.py data\videos\其他视频.mp4 10
python tools\prelabel.py 0.3          :: 先自动标一遍，再手工改，能省大半力气
:: 用标注工具打开 data\dataset\images 改标注，存 YOLO txt 到 data\dataset\labels
python tools\split_dataset.py         :: 按摄像头分组划分，防止同机位的图两边都出现
python src\07_train.py
```

标注标准：肉眼能认出是车的都框，认不出的都不框。远处的小车要框——只框中间的大车，模型会学会忽略远处。骑电动车的人、行人、自行车不框。

混训踩过一次坑：第 2 轮用 Intersection-Flow-5K 6928 张整个替换掉 UA-DETRAC 接着训，结果 test3/test4 反而更差，属于灾难性遗忘，只能退回旧模型。下次要么新旧按比例混着训，要么别换数据集。

## 二、关键参数怎么定

计数线的 y 不是猜的，两条路。

自动扫，先用这个：

```bat
python tools\sweep_line.py data\videos\test3.mp4 200
```

它打印每个高度各有多少辆车穿过。挑次数多、又不在车排队等红灯那一带的高度。

手工画：

```bat
python tools\grab_frame.py data\videos\test1.mp4 1
:: 用画图工具在该图上绘制一条线，另存为其他文件名（不要覆盖原图）
python tools\read_line.py data\samples\test1_frame1.jpg data\samples\line_drawn.jpg --write configs\test1.json 0
```

该脚本比对两张图的差异拟合出直线，并生成核对图供确认。

ROI 两条规矩。一，不能贴计数线，要留出一个车身的助跑区，否则车刚进视野就到线上，跟踪器还没看清就过线，必漏。二，多边形只用来过滤框中心，裁剪用的是它的外接矩形，所以把区域外涂黑反而会检出更多垃圾框。

## 三、输入尺寸

监控画面里车很小，YOLO 默认压到 640×640，远处的车基本消失。同一张 1920×1080 的图实测检出数量：

| 输入尺寸 | 检出的车 |
|---|---|
| 640 | 29 |
| 960 | 51 |
| 1280 | 71 |
| 1600 | 84 |

裁出中心区域再送进去，效果更明显。同一张图测过：

| 做法 | 中心区检出 | 耗时中位数 |
|---|---|---|
| 整图 → 640 | 21 辆 | 32 ms |
| 整图 → 1280 | 32 辆 | 103 ms |
| 裁中心 960 → 640 | 31 辆 | 48 ms |
| 裁中心 960 → 800 | 37 辆 | 73 ms |

所以 ROI 裁剪不只是为了排除干扰，它本身就等于放大。

但当前全链路是 640：训练 640、配置 640、ONNX 640、RKNN 640。1280 只在实验里测过检出数，没有真跑起来。原因是训练尺寸与部署尺寸必须一致，启用 1280 要重新训练、重导 ONNX 与 RKNN，还要在板子上复测帧率。这件事没做，是目前精度的主要缺口。

## 四、INT8 量化掉了多少精度

同一份权重导出三个模型，在验证集 1510 张（10795 个标注框）上对比。评估口径 conf=0.001、NMS IoU=0.7，单类。

| 模型 | mAP50 | mAP50-95 | 每图框数 |
|---|---|---|---|
| ONNX FP32 | 0.9426 | 0.7196 | 26.1 |
| RKNN FP16 | 0.9426 | 0.7191 | 26.2 |
| RKNN INT8 | 0.9037 | 0.6125 | 26.2 |

INT8 相对 FP32：mAP50 下降 3.9 个百分点（4.1%），mAP50-95 下降 10.7 个百分点（14.9%）。损失主要在定位精度——坐标量化步长 2.5 px，匹配框中心平均偏移 1.86 px；每图框数 26.1 → 26.2，检出能力不变。FP16 与 FP32 在本口径下无可测差异，可视为无损。

INT8 转换前必须先拆分输出头（boxes + scores 两路输出），否则坐标与分数共用一个量化参数，0～1 的分数会被压成 0。生成脚本为 `tools/01_convert/make_head3.py`，板端 C++ 会自动识别双输出。

2026-11-02 补充：上表那个「匹配框中心平均偏移 1.86 px」是在 640 空间测的，折算原图约 6.75 px。该偏移现已修复到 0.03 px，做法是把模型输出从坐标改为 DFL 距离，原理见 [head4_原理详解.md](head4_原理详解.md)。

## 五、工具脚本

`tools/` 下有 50 多个脚本，按用途分了 5 组，完整清单和用法见 Python 仓库的 [tools/README.md](https://github.com/ImJRong/multi-road-crossing-vehicle-count/blob/main/tools/README.md)。最常用的几个：

| 工具 | 干什么 |
|---|---|
| `tools/01_convert/make_head4.py` | 生成 head4 的 ONNX（带自动校验） |
| `tools/01_convert/verify_head4_decode.py` | 验证距离→坐标公式，差值必须是 0 |
| `tools/02_diagnose/ch_scan.cpp` | 判断模型好坏：打印 4 个通道各自的范围 |
| `tools/02_diagnose/batch_box_eval.py` | 批量对比两个模型的框误差 |
| `tools/04_dataset/read_roi.py` | 读取图上手绘的 ROI 并写入配置 |
| `tools/04_dataset/read_line.py` | 读取图上手绘的计数线，支持 `--base <底图>` |
| `tools/04_dataset/extract_frames.py` | 抽帧做训练数据 |
| `tools/04_dataset/prepare_detrac.py` | 把 UA-DETRAC 转成 YOLO 格式 |

## 六、已知问题

- 官方 YOLOv8n 没在路口监控的机位和光照上训练过，远景小车、被遮挡的车会漏检。这是要自己标数据微调的原因。
- 跟踪 ID 会断。车辆被遮挡或漏检一帧即分配新编号，所以不能拿「出现过的 ID 数」当车流量，得用穿线计数。
- 红绿灯和杆子会被检成车（置信度 0.37 左右）。调 `conf` 去不掉，因为远处真车也在这个区间。静止过滤能让它不计数，但根治要标数据。
- test4 那辆被植被挡住的白色轿车，模型直接漏掉，至今没解决。
- 静止过滤有副作用：等红灯的车在开动前不画框。计数不受影响，因为过线那一刻它已经在动了。
